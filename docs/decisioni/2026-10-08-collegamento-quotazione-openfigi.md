# 2026-10-08 — Linking an imported instrument to a listing (OpenFIGI)

- **Problem**: the IBKR/DEGIRO import creates `manuale` instruments with only the ISIN (prices from the statement). Without a Yahoo symbol they have no automatic prices or profile (sectors, holdings), so they stay out of diversification and overlaps.
- **Solution**: on the security page, "Prezzi automatici" ("Automatic prices") card → `GET /api/instruments/[id]/quotation` asks OpenFIGI for the ISIN's listings (`lib/market-data/providers/openfigi.ts`, only Milan, Xetra, Amsterdam, London, Switzerland, Paris, USA), Yahoo confirms they exist **in the statement's currency**, at most 3 are proposed. `POST` links: it adds the symbols and switches to `priceMode: "auto"`, then the history fetch starts from the first operation.
- **Choices**: linking is always manual (OpenFIGI estimates the symbol, Yahoo confirms, the user chooses); the instrument stays private to the user (no merge with the shared instruments: it would touch ~13 tables). `findBySymbol` now searches only among shared instruments, so the symbol of a private instrument is not reused by others. Manual prices remain saved but the page shows the automatic ones. No operation to unlink.
- **Limits**: OpenFIGI without a key allows 25 requests/min (`OPENFIGI_API_KEY` optional); the `exchCode` → Yahoo suffix table (`OPENFIGI_EXCHANGE_SUFFIX`) covers the main exchanges, the others are ignored. Real test on 4 ISINs: all found, with hundreds of listings each, hence the filter.
- **CSV import and search by ISIN**: if Yahoo does not find an instrument with an ISIN (`resolveIdentity`) or the instrument search receives an ISIN with no results, OpenFIGI proposes the listings and Yahoo confirms them (`lib/investments/isin-listings.ts`). In the import the proposal is always "Da controllare" ("To check": name and type come from OpenFIGI) and uses the file's currency; in search they are shown without a currency filter. The IBKR/DEGIRO path does not change (manual instruments with prices from the statement, linked later from the security page).
