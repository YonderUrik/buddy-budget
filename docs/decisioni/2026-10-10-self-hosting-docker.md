# Self-hosting with Docker Compose and images on ghcr.io (2026-10-10)

- **Registry**: ghcr.io remains the single registry (it is already the deploy one). Free and without pull limits for public packages, same login/permissions as the repo, publishing with `GITHUB_TOKEN`, no account to manage. Docker Hub: anonymous pull limits per IP (in the dev sandbox it answered 429 even for base images), a second account to maintain, advantage only in discoverability. A Docker Hub mirror will be considered only if visibility is needed, or an application to the Docker-Sponsored Open Source programme.
- **Compose** (`docker-compose.yml`): app, Postgres 17, Redis 7, `migrate` job at every start and a `cron` service that calls the `/api/cron/*` endpoints at production times (GoCardless jobs only if configured). Port on 127.0.0.1 by default; HTTPS is done by a reverse proxy.
- **Optional integrations**: Google, Resend and GoCardless are no longer mandatory at startup (`lib/env.ts`, empty string = absent). Without Resend the magic link goes to the app's stdout (`lib/auth/magic-link-log.ts`, never in `logger`), without GoCardless manual accounts and CSV import remain. In production nothing changes: the keys are there.
- **Publishing**: multi-arch (amd64+arm64), `latest` tag and SBOM are behind the repo variable `SELFHOST_IMAGES=true`; when off, releases are identical to before. Postponed: cosign signing, Docker Hub mirror, AI CSV worker in the compose, Google button hidden when not configured.
