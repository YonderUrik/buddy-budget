# Categorization: confident categories are applied automatically (2026-10-12)

Date: 2026-10-12

Before, every proposal went through the cards, even obvious ones, and it was not clear whether a category came from a rule, from past choices or from the AI. Decision (Daniele's request): the user decides only what is uncertain and always sees what was applied automatically.
- **What is applied automatically**: rules always (also in CSV imports, which previously did not use them); with the option «Lascia che l'app scelga quando è quasi certa» ("Let the app choose when it is almost certain", Impostazioni → Assistente per le categorie, on by default) also proposals at least 90% confident (`AUTO_APPLY_THRESHOLD`). Past choices count only with at least 3 agreeing transactions, with confidence = agreement share × similarity; the AI only with consent active. Whoever had consented to the AI before this rule starts with the option off (migration 0034) and finds in Categorizza a prompt to turn it on.
- **Trace**: each transaction has `category_source` (rule, history, assistant, user), `category_confidence` and `categorized_at`. Categorizza has two tabs: «Da decidere» ("To decide": cards or list) and «Messe dall'app» ("Set by the app": one-tap correction, «Va tutto bene» — "All good" — marks as seen up to the last one shown, `auth_user.auto_categorized_seen_at`). In Movimenti the row shows the origin icon («Regola», «Le tue scelte», «AI» — "Rule", "Your choices", "AI" — in the tooltip).
- **Logos**: from the brand dictionary (`MERCHANT_LOGO_DOMAINS`), then from the website written in the transaction («NETFLIX.COM», intermediaries like PayPal excluded), then (Daniele's choice) from the name search on Logo.dev (`/v2/search`, secret key `LOGODEV_SECRET_KEY`, optional) only for expenses, never bank transfers, with a name seen in the transactions of at least 3 users (HyperLogLog of fingerprints on Redis) and accepted only if the name found is identical; at most 100 searches per day, result cached for everyone. The server signs (HMAC) the sites and names it puts in the groups, so the route does not ask Logo.dev for arbitrary domains or names; the browser only talks to us; fallback to the initial.
- **Legal texts**: Privacy updated (confident proposals applied automatically, always indicated and correctable) without changing `LEGAL_VERSION`: automatic application by the AI stays tied to consent and to the option, both revocable.
- **Observability**: `buddybudget_categorization_auto_total{source,event=applied|corrected}` (the share of corrections is the measure of the threshold's errors), logs `categorization.auto.applied|corrected|reviewed|setting.updated`, Umami events `categorization_auto_*`.
- **Flow fixed (second pass, same PR by Daniele's choice)**: a new or changed rule applies immediately to «Da categorizzare» ("To categorize") transactions (including «Ricordala», "Remember it", in Movimenti, which now replaces the merchant's rule instead of failing); deleting a category puts its transactions back to «Da categorizzare» without origin; the sync summary counts after the automatic pass («N categorizzate da sole, M da decidere», "N categorized automatically, M to decide"); broker imports and transactions added by hand go through the rules; the CSV import cleans the merchant name and puts transfers and securities legs into transfers; a single «Da decidere» number (badge, Movimenti, Categorizza) and a row in the summary email; removed the old Ollama path.
- **Ricategorizza** ("Recategorize", migration 0035, tables `categorization_runs`/`categorization_run_items`): in Categorizza it redoes the automatically set categories with today's rules and, with the option active, the confident proposals (evidence only from the user's choices, never from automatic categories). Preview per merchant with checkboxes; transactions from before the origin tracking only if requested (they may be user choices) and never those split by hand; `utente` choices never. After a rule, «Cambiali» ("Change them") applies it to past ones too. Undo from the toast or the dialog for 7 days, only on transactions nobody touched afterwards; rows kept 30 days. **Exception to the jobs standard**: synchronous, because it only does DB reads and writes in one transaction, without calling the assistant (it does not ask for new proposals: it uses those already saved).
- **Observability added**: `buddybudget_categorization_auto_total{event=recategorized|recategorize_undone}`, logs `categorization.rule.created|replaced|updated`, `categorization.recategorize.previewed|applied|undone|failed`, Umami events `categorization_rule_saved`, `recategorize_previewed|applied|undone`.
- **Simplified for non-experts (third pass, same PR)**: no percentages in view (confidence stays in the tooltip), «Fatte da sole» ("Done on their own") becomes «Messe dall'app», the option is called «Lascia che l'app scelga quando è quasi certa» and the copy says «quasi certa» ("almost certain") instead of «sicura al 90%» ("90% sure"); Ricategorizza goes into the page's «⋯» menu and the transactions from before the origin tracking appear in the same list unticked («forse scelti da te», "maybe chosen by you") instead of behind a checkbox; the «Cambiali / Lasciali così» ("Change them / Leave them as they are") question after a rule stays until a choice is made.
