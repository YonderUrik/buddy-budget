# Screenshots in every language and browser language detection (2026-10-17)

- **Decision**: the landing screenshots are captured in every app language (Italian, English, German) and the landing shows the ones in the visitor's browser language; the app proposes the browser language to whoever has not chosen one.
- **Why**: the app is multilingual but the screenshots were Italian only, and the language was never detected (signed out it was always Italian unless picked by hand).
- **How**: `DEMO_LANGUAGE` seeds the demo in a language (`scripts/demo-seed-texts.ts`, German with German product rules), `CAPTURE_LANGUAGE` captures into `public/screens/<language>/` at the Italian sizes, the daily bot loops over the three languages. The landing renders every version and a pre-paint script picks one (`<html data-screens>`, `?lang=` to force); screens hidden by German rules fall back to English. App: `detectLanguage` reads `Accept-Language` when there is no saved choice (signed out, or onboarding not finished); unsupported languages get English, no header keeps Italian; German proposes the German product.
- **Formats**: the hardcoded `it-IT` number, percent and date formats (chart labels, investments, categorisation, analytics, debts, fields) now follow the user's locale, with Italian output unchanged; prefilled number fields use the locale's decimal separator.
- **Remaining text**: words inside formatted values, analytics sentences, sync messages, the version label and the debt/account amount parsers (`parseLocaleNumber`) follow the user's language. Emails (summary, alerts, magic link, account, bank consent, imports) are written in the recipient's saved language (`lib/email/locale.ts`; the magic link uses the language of the sign-in page for new users). API error messages stay Italian in the code: `withRoute` translates the `error` of every JSON error response into the request's language through the catalogs (`lib/localization/route-errors.ts`), and client query fallbacks use `pageText`.
- **Deferred**: landing texts in English/German (separate thread); dynamic server messages built with values (some import row errors) stay Italian; AI prompts and the export readme stay Italian; reports sent to the support inbox stay Italian; per-language OG image.
