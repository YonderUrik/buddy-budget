# 2026-10-18 — API foundations for the native apps

Data: 2026-10-18

The native iOS/Android apps (spec in the separate `buddy-budget-mobile-spec` repo, `api/auth.md` R1/R7/R8 and `api/gaps.md` G1/G13) need to call the existing API without a browser cookie jar. Decided: (1) the better-auth `bearer()` plugin, so `Authorization: Bearer <session token>` works on every route and in the proxy, with the token returned in the `set-auth-token` header at sign-in; the web keeps the HttpOnly cookie, no CORS change (native clients are not browsers). (2) Public `GET /api/legal` with the current `LEGAL_VERSION`, the clauses to approve and the document links. (3) The proxy's gate 403s for APIs now carry `{ code: "account_deactivated" }` and `{ code: "legal_acceptance_required", version }` (pages still redirect). (4) `GET /api/me/bootstrap`: profile, the gate to show and the country capability map, open through every gate; gates live in `lib/account/gates.ts` and capabilities come from `isCountryPathAvailable`, one source for proxy, web and apps. (5) Personal-import writes skip the Origin check only for bearer requests without cookies (`lib/http/same-origin.ts`).

Why bearer and not JWT/cookie jars: no route changes, sessions stay revocable from Impostazioni, and the 7-day sliding expiry works the same. Then (same branch): native sign-in with a 6-digit emailed code (better-auth `emailOTP`, R2): codes stored hashed, valid 10 minutes, 3 attempts, implicit sign-up as with the magic link; outside production an undeliverable code is written to the log as `auth.otp.dev_code` so simulators can sign in, never in production. `pnpm dev:mobile-session --email <test address> [--demo]` (dev only: refuses NODE_ENV=production and non-localhost databases; `--demo` only for reserved test domains) creates an onboarded user, optionally with the public demo's sample data, and prints a bearer token for simulators. Phase 2 (ADR 0002 of the spec, thin clients): view endpoints that run the web's own functions on the server, never a copy of them: `GET /api/overview` (net-worth series, composition, month pace, voice, renewal alerts), `GET /api/liquidity/month` (month figures, groups, budget progress), `GET /api/accounts?include=trend,health`, paged `GET /api/transactions?limit&cursor` with the Movimenti filters (the legacy array is unchanged without `limit`/`cursor`; text search runs on decrypted rows, so it reads the window whole), default category names localized on the server (`/api/categories`, rule `categoryName`), and a stable `code` on every error body (`lib/http/api-error.ts`, generic fallback in `withRoute`). Phase 3 (same branch): `GET /api/liquidity/analysis` (Analisi: period spend vs the period before, cumulative curve and typical month, spend by group and category with scaled budgets, income sources, accumulated savings; the lead sentence moved to `lib/liquidity/analysis-sentence.ts`, shared with the web page); the Investimenti tabs: `GET /api/investments/view` (Portafoglio, Diversificazione, Operazioni: `buildInvestmentsView` plus what the cards derive, the four reinvest-costs/taxes scenarios precomputed) and `GET /api/investments/performance` (returns, the returns card's figures at every chart point via `computePortfolioReturns(asOf)`, sampled to 160 points on long series, risk reading, the four heatmaps), and for Italy `GET /api/investments/income`, `GET /api/investments/taxes` and `POST /api/investments/taxes/simulate-sale` (pure `simulateSale`, no writes; DE gets 403 `country_feature_unavailable`, its tabs are the financial plan). All take the web's broker filter as `excludeBrokers`. `GET /api/pension/view` (Italy): what the Pensione tabs compute for one fund, with the exit-tax timeline for every year 0–35 (the drag only indexes into it); the projection sliders stay on the device, their settings now in `lib/pension/projection.ts`, shared with the web. `GET /api/debts?include=insights`: interest shares, repaid share per debt and the «come uscirne prima» avalanche plan for every slider step (`buildDebtsInsights`, slider settings and `repaidShare` moved to `lib/debts/overview-insights.ts`). `GET /api/analytics/base` (Italy): the eight queries of Analitiche in one call, with base, assumptions in use, return source, FIRE plan and the saved plan's growth and timeline readings; the «e se…» sliders and Monte Carlo stay on the device. `/api/financial-planning` now answers Italy with the coded `country_feature_unavailable` 403 (and `invalid_plan`/`plan_changed` codes), and the bootstrap's `sections.financialPlanning` is false for Italy (no planning model). Open: Google client IDs, Sign in with Apple, the GoCardless return flow without cookies, `GET /api/meta` for the remaining constants. No migration, no impact on the landing.
