# Imports of movements already present (2026-10-19)

**Decision**: uploading a CSV/Excel file that was already imported is refused at once, before any AI analysis, whatever source the user picks («Questo file è già stato importato: i suoi movimenti ci sono già tutti.», `409 already_imported`). A different file whose rows are partly there imports only the new ones, and the receipt, the list, the island and the email say «12 su 40 movimenti importati: gli altri c'erano già.», or «Niente di nuovo da importare» when none is new. No migration: the counts live in `importLedger` (`rows`, `alreadyPresent`).
**Bug found**: row dedup worked only within one source. The upload form opens on «Nuova banca o broker», so the same file uploaded twice that way was read with a new format, no receipts, and every movement entered twice in a second «· CSV» account. Rows are now looked up in every source of the user, and a new source whose duplicates all come from one other source adds its new rows to that source's account and portfolio.
**Unchanged**: broker statements (IBKR, DEGIRO, Trade Republic) already answered «Non c'è niente di nuovo da importare» for the same file; partly overlapping statements stay refused, since they are reconciled by period.
**Why**: Daniele asked to check that the same file is rejected and an overlapping one adds only the N new movements, with a message saying how many.
**Signals**: log `personal_import.already_imported` (upload refused) and `personal_import.saved` with `count`, `total`, `skipped` (already present); Umami `personal_csv_already_imported` with `stage` `caricamento|analisi`. Living doc: `docs/architecture/bank-sync-and-imports.md` §4.8–4.9.
