# Import audit: valid files that failed or were read wrong (2026-10-31)

After the DEGIRO failure, Daniele asked for the import to be rock solid. Three audits (built-in readers, exchange rates and valuation, the AI worker) and a run with his real IBKR, DEGIRO and Trade Republic files found a class of bugs: valid input that failed three times and ended in the generic error, or was imported wrong without saying so. Fixed in PR #543:
- **Wrong or missing prices**: securities after the 25th of a big statement became manual (OpenFIGI throttling): background searches now retry (`patientSearches`). A non-euro security without the broker's exchange tries its currency's main exchange first (Meta to `META`, not `0QZI.L`). A corporate-action copy keeps the broker's prices for good (`instruments.keep_broker_prices`, migration 0054): the automatic link no longer undoes it. The FX cron also covers currencies held only through manual securities.
- **Data in the wrong place**: hand-typed, Fineco and Yahoo operations went to the oldest portfolio, possibly an IBKR one whose next statement deletes them; now the portfolio without a broker. Every broker gets its own portfolio (Daniele's ask): a new DEGIRO account no longer joins the one of hand-entered operations, and Fineco and Yahoo Finance exports get «Fineco» and «Yahoo Finance» (imports made before stay where they are). A blank or header line shared by two banks' files made the second bank adopt the first one's account.
- **Valid files refused**: bonds (Fineco at 100× the value, the AI path refused every BTP), zero-price buys (spinoffs, staking), Bitpanda staking/stock rows and fees in crypto, today's movements between midnight and 2 a.m. (UTC date), pence written «GBp».
- **Silent or stuck failures**: source outages in the readers now retry the job instead of saving manual securities or calling the AI; readers run a dry run before writing; the accepted parser is saved before the exchange rates, so a retry makes no model call; a `ready` job that cannot be saved fails after 5 retries and emails the user and support instead of expiring unnoticed.
- **Deleted broker imports could not come back**: a deleted IBKR statement's file was refused as «already imported» (the job outlived its data); files read by a built-in reader now go to the reader, which knows what it already has.
- **A trial run that disagreed with the real import**: with a shared Liberty Global next to the user's own copy, the dry run counted the position on the shared one and refused the 2024 IBKR statement (217 vs 370 shares); lookups by ISIN now take the user's own copy first, in the dry run and in the import. A blank column name in the model's layout (`""`) no longer throws away its whole answer.
Deferred: progress label per phase (needs a stored phase), non-UTF-8 files, sign in a separate D/A column, two workers racing on one source.
