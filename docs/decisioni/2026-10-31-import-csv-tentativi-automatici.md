# Personal CSV import: automatic retries, no rows to fix (2026-10-31)

Daniele wants the CSV import to be "drop the file and it works". The user picks a bank (or types a new name) and uploads; a parser is created on first use and reused afterwards. When it fails, the worker tries again by itself: Flash fresh, Flash with the last rejection (its parser, the reason, up to 50 failing lines, the header columns the metadata does not declare), then Flash with every rejection, 200 failing lines, reasoning on and a 131,072-token output. No Pro model: the newest DeepSeek Pro on OpenRouter is a generation older than v4.1 Flash. After the third rejection the user sees one message and support gets a report with every attempt.
A parser now also fails when a header column is missing from its metadata, and every call carries hints with no personal data (user currency for files without one, today, day/month order of the country, a bank/broker guess). A bank that changes its layout gets a new parser version.
Replaces the «Righe da controllare» screen of 2026-10-15: no partial import, no «importa saltando», no «rianalizza»; `review_failed` is no longer reached and leftover jobs expire. Duplicates: line keys as before, a line read differently by a new parser counts as present instead of blocking, and new lines whose exact date, amount and description (or trade fields) are already in the source's account or portfolio are skipped, counted as a multiset. No fuzzy matching.
No migration. Spec `docs/superpowers/specs/2026-10-31-csv-import-ladder-design.md`, living doc §4.8–4.9 of `docs/architecture/bank-sync-and-imports.md`. Deferred: sharing parsers between users, telling the model a file came from Excel (needs a column), the first-call improvements of spec §6 (eval set first).
