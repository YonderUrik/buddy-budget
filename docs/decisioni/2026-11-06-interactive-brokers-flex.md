# Interactive Brokers through the Flex Web Service

Data: 2026-11-06

Interactive Brokers connects read-only with a Flex Web Service token and a Flex Query ID, never a username or password and never trading, from «Nuovo conto» like Trade Republic (and `/connections/interactive-brokers` for status, sync, reconnect and disconnect). The Flex XML is rewritten into the same records as the English Activity Statement CSV and read by the existing IBKR reader, so a Flex report goes through the reconciled statement import (cash per currency, NAV, positions, period continuity, all or nothing) and shares one history with the account's CSV statements (same account key). The sync asks for periods with `fd`/`td`: from the account's opening in chunks of at most 365 days, then the latest period re-requested whole (it replaces itself and picks up IBKR's corrections) until it would pass 365 days. A report that does not reconcile is never saved. Tokens are AES-GCM encrypted (`DATA_ENCRYPTION_KEY` required), SendRequest is limited on Redis to 1 per second and 10 per minute per token, GetStatement polls 1019 with bounded backoff, an expired or invalid token stops the automatic syncs, and other failures back off from 1 hour to 1 day. Hourly cron `ibkr-flex-sync`. Migration 0056 (`ibkr_flex_connections`). Living doc: §4.12 of `docs/architecture/bank-sync-and-imports.md`.

**Launch dependency:** `IBKR_FLEX_CONNECTIONS_OPEN` unset = closed on the hosted version and open on self-hosted installs. A hosted service using customers' Flex tokens stays closed until IBKR confirms in writing that this is allowed. Catalog status `soon` until then.

**Assumption to verify on the first real connection:** IBKR's official docs pages returned 403 to automated reads during this work, so the optional `fd`/`td` period parameters, the error codes and the XML layout come from IBKR's widely documented v3 behaviour. `ibkr_flex.connect.succeeded` logs `periodHonoured`. If IBKR ignores `fd`/`td`, the query's own period is imported once and the sync stops asking (`ibkr_flex.sync.period_mismatch`).

Deferred: corrections IBKR makes inside periods older than the latest are not re-fetched; a «Riallinea da…» action; the «Aggiungi» entry (it would show to every hosted user while the connection is closed there); options, futures and bonds stay out, as in the CSV import; amounts are JS numbers parsed from IBKR's decimal strings and summed with the existing reader's tolerances, not a decimal library.
