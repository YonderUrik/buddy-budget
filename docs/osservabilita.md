
### Direct Trade Republic

`trade_republic.login.started|completed|failed` and `trade_republic.sync.completed|failed` report sign-in and background cash refresh outcomes without provider bodies or credentials. Query `buddybudget_trade_republic_requests_total{action="login"|"sync",outcome="success"|"error"}` for counts and `buddybudget_trade_republic_request_seconds` for duration. `trade_republic.login.failed` and `trade_republic.sync.failed` carry `diagnostics`: the trail of the attempt (HTTP statuses, socket open/close and error-frame codes, payload shapes, event type/status counts, every rejected check grouped with the structure of one example item, unexpected error classes). It holds structure, provider enums, counts and masked formats only, never titles, amounts, IDs, cookies or credentials, and is enough to update the parser from one line. `trade_republic.sync.incomplete` (warn) carries the same trail when a successful sync skipped unknown event types (`unrecognized`) or the timeline does not add up to the balance (`reconciled=false`); `buddybudget_trade_republic_unrecognized_events_total` counts skipped events. Loki: `{service="buddy-budget"} |= "trade_republic.sync.incomplete"` lists the types to add. `trade_republic.investments.completed` (`inserted` operations, `created` instruments, `enabled` = quantities checked against TR positions) and `trade_republic.investments.failed` (with `diagnostics`) report the securities part of each sync; `buddybudget_trade_republic_requests_total{action="investments"}` counts its outcomes. Adapter problems also email support (`SUPPORT_EMAIL_TO`, else support@buddybudget.io on the hosted version; nothing on a self-hosted install without it): failed sign-in, sync or investment import with reason `invalid-response`, `unsupported-event` or `internal`, and syncs that skipped unknown event types. The email carries the same diagnostic trail and the hashed user, once a day per distinct problem (Redis key `trade-republic:support:<signature>`); user-side outcomes (wrong PIN, expiry, rate limit, network) never email. `trade_republic.support.sent|failed` log the delivery. On staging (`APP_URL` = staging.buddybudget.io) the same steps are also logged live as `trade_republic.debug.*`. Umami records `trade_republic_login_started` and `trade_republic_connected`; manual updates retain `account_sync_manual`. Before production rollout, add these metrics to the banking dashboard in the infrastructure repository. Staging verifies the new feature without changing production dashboards.
