# BuddyBudget mobile (Capacitor)

Native iOS and Android app of BuddyBudget. The WebView loads the deployed web app (`https://app.buddybudget.io`), so
the screens are the web ones and every web release reaches phones without a store update. The shell adds what the
web cannot do: links and the bank coming back into the app, Google and Apple sign-in sheets, push notifications,
Face ID / fingerprint lock, Android back button, status bar, icons and splash.

Design: [`docs/superpowers/specs/2026-10-17-native-app-capacitor-design.md`](../docs/superpowers/specs/2026-10-17-native-app-capacitor-design.md).
Rules for future work: "Mobile app (Capacitor)" in the root [`CLAUDE.md`](../CLAUDE.md).

## Layout

- `capacitor.config.ts`: app id `io.buddybudget.app`, `server.url` (override with `BUDDYBUDGET_APP_URL`), user agent
  suffix `BuddyBudgetApp`, plugin options (sign-in providers, push presentation, edge-to-edge bars, splash).
- `www/`: only the offline page shown when the server cannot be reached.
- `scripts/generate-assets.mjs` (`pnpm assets`): icons and splash from `public/brand/logo-mark.svg`.
- `scripts/sync-version.mjs`: copies the `package.json` version (bumped by release-please) into the iOS project;
  Android reads it in `android/app/build.gradle`. `pnpm sync` runs it before `cap sync`.
- `ios/`, `android/`: generated by `cap add`, then edited by hand (keep these edits when regenerating):
  - `ios/App/App/App.entitlements`: Associated Domains `applinks:app.buddybudget.io`, push (`aps-environment`),
    Sign in with Apple.
  - `ios/App/App/Info.plist`: URL schemes `buddybudget` and the reversed Google iOS client id
    (`GOOGLE_IOS_REVERSED_CLIENT_ID` build setting in `project.pbxproj`), `NSFaceIDUsageDescription`.
  - `ios/App/App/AppDelegate.swift`: hands the APNs token to the push plugin.
  - `ios/App/App/PrivacyInfo.xcprivacy`: privacy manifest (no tracking; data types as in the privacy policy).
  - `android/app/src/main/AndroidManifest.xml`: App Link on `/api/auth/magic-link/verify` and scheme `buddybudget://open`.
  - `android/app/build.gradle`: version from `package.json`, release signing from `keystore.properties`.

The web side lives in the app: `lib/native/` (every plugin call, dynamic imports only), `components/domain/native/`
(`NativeAppBridge` in the root layout; `NativeSessionTasks` and `BiometricLockScreen` in the app layout),
`lib/push/` (sending), `app/.well-known/*`, `app/api/native/config`, `app/api/gocardless/app-return`,
`app/api/user/push-devices`.

## Run it

Requirements: Node + pnpm; Xcode 26 (macOS) for iOS; Android Studio with JDK 21 for Android.

```
cd mobile
pnpm install
pnpm sync          # version into iOS, then config and plugins into ios/ and android/
pnpm ios           # opens Xcode: pick a simulator or a device and Run
pnpm android       # opens Android Studio
```

Against a local server: `BUDDYBUDGET_APP_URL=http://192.168.1.10:3000 pnpm sync` (the phone must reach your machine;
`cleartext` is turned on automatically for http). Universal/App Links, Google, Apple and push only work against the
real domain and with the real credentials below. CI (`.github/workflows/mobile.yml`) builds an unsigned Android debug
APK (downloadable from the run) and an iOS simulator build on every change to `mobile/` or to the plugin versions.

## Accounts and credentials (once)

| What | Where | Then |
|------|-------|------|
| Apple Developer Program (99 $/year) | developer.apple.com | Team ID; App ID `io.buddybudget.app` with Associated Domains, Push Notifications, Sign in with Apple |
| APNs key (`.p8`) | Certificates → Keys | `APNS_KEY`, `APNS_KEY_ID`, `APNS_TEAM_ID` in the app Secret |
| Google Play Console (25 $ once) | play.google.com/console | Play App Signing certificate SHA-256 → `NATIVE_ANDROID_CERT_SHA256` |
| Firebase project (free) | console.firebase.google.com | Android app `io.buddybudget.app` → `google-services.json` in `android/app/` (not committed); service account JSON → `FCM_SERVICE_ACCOUNT` |
| Google OAuth clients | Google Cloud console, same project as the web client | iOS client → `GOOGLE_IOS_CLIENT_ID` and its reversed id in `GOOGLE_IOS_REVERSED_CLIENT_ID` (`project.pbxproj`); Android client with package + SHA-1 of debug and Play certificates |
| Universal/App Links | app Secret | `NATIVE_IOS_APP_ID` (`<TEAM_ID>.io.buddybudget.app`), `NATIVE_ANDROID_PACKAGE`; check `/.well-known/apple-app-site-association` and `/.well-known/assetlinks.json` |
| Sign in with Apple | app Secret | `APPLE_APP_BUNDLE_IDENTIFIER=io.buddybudget.app` |
| Android upload key | your machine | `keytool -genkey -v -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000`, then `android/keystore.properties` with `storeFile`, `storePassword`, `keyAlias`, `keyPassword` (never committed) |

## Store release

1. Merge the release PR (release-please bumps `mobile/package.json` with the app).
2. `pnpm sync` (iOS version and build number), then:
   - iOS: Xcode → Product → Archive → Distribute (TestFlight first). Set `aps-environment` to `production` in
     `App.entitlements` for store builds if Xcode does not do it with the distribution profile.
   - Android: `cd android && ./gradlew bundleRelease` → upload `app/build/outputs/bundle/release/app-release.aab`.
3. A store release is needed only when the native side changes (a plugin, an entitlement, icons, the shell config):
   screens and APIs reach phones with the normal web deploy.
