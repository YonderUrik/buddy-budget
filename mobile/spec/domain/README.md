# Domain rules: what mobile computes vs. displays

This folder specifies every **user-visible calculation** of BuddyBudget so the iOS (SwiftUI) and Android (Compose) apps produce the **same numbers and the same text** as the web (Next.js 16, `lib/calc/*`, `lib/*`).

- `domain/<topic>.md` covers formulas, rounding, edge cases, constants, and where the calculation runs today.
- `domain/vectors/<topic>.json` holds **golden test vectors** generated by running the web's TypeScript (`npx tsx` against the repo, read-only). Both apps load these files in unit tests. They are the parity contract.
- `domain/locale-data/locale-data.json` holds locale tables exported from the web's ICU (see formatting-localization.md).
- `domain/tools/*` contains the generator scripts. Run them from the web repo root with `npx tsx --tsconfig tsconfig.json <script> <outdir>` to regenerate after a web change. Some generators (debts, planning) write their output path or argument conventions slightly differently; check the header of each script.

## 1. The big picture

The web is a **thick client**. Many API routes return raw rows (transactions, operations, prices, snapshots, debts' terms and events), and the browser computes most KPIs, charts and simulators (`"use client"` components and `lib/queries/*-view.ts`). Copying that architecture would make every number a cross-platform port.

### Recommendation
1. **Server-first for everything that isn't interactive.** Add thin "view" endpoints that run the **existing** TypeScript functions on the server. Most of them are already pure and already used server-side for emails, the sidebar and cron jobs. Mobile only displays their results. Each endpoint below removes a whole port.
2. **Port 1:1 only the interactive simulators.** These are sliders, live form previews and drag-to-inspect charts, where a network round-trip per tick is unacceptable. They are pure functions with no I/O, and the vectors pin them down.
3. **Port the small pure helpers that the UI needs in any case**: formatting, date and period navigation, split ("Dividi") maths, sorting. These are cheap and covered by vectors.

## 3. Shared conventions for ports

1. **Numbers.** The web uses IEEE-754 `Double` everywhere (`Number(...)` of Postgres numeric strings). **Use `Double` on both platforms**, not `Decimal` or `BigDecimal`. Matching the web bit-for-bit requires the same arithmetic and the same order of operations. A decimal type would "fix" values the web shows differently. Parse amounts from the API's decimal strings with `Double(string)` / `toDouble()`.
2. **Rounding.** `round2(x) = Math.round(x*100)/100`. JS `Math.round` rounds **half toward +∞** (`Math.round(-2.5) = -2`). Implement it as `floor(x*100 + 0.5)/100`. Never use Swift `.rounded()` (half away from zero), Kotlin `roundToInt`/`Math.rint` (half even) or `BigDecimal.HALF_UP`. Some modules add a `Number.EPSILON` nudge (see debts.md and financial-planning-de.md); port it literally where it appears. Round **only where the web rounds**. Each spec says where.
3. **Dates.** Data dates are `YYYY-MM-DD` calendar strings. Parse them as local calendar dates (`LocalDate`, or `DateComponents` with the Gregorian calendar) and never through UTC instants. Two date-arithmetic flavours exist and both must be ported: `addMonths` with **JS overflow** (31 Jan + 1 month = 3 Mar) and `addWholeMonths` / `subtractMonthsClamped` with **clamping** (= 28 Feb). Each spec names which one applies.
4. **"Today".** Liquidità, net worth and investments use the **device-local** date. Debts and the German editors use the **UTC** date (`toISOString().slice(0,10)`). Notifications use `Europe/Rome`. Inject `today` into every ported function (no hidden `Date()` calls) so tests stay deterministic.
5. **Sorting.** JS `Array.prototype.sort` is **stable**. Swift's `sort` is not guaranteed stable, so add the original index as a tie-breaker. String comparison in the web is either code-unit order (`<`) or `localeCompare(_, "it")`; the specs say which.
6. **Math functions.** `Math.exp`, `log`, `pow` and `cos` in V8 are fdlibm ports. Kotlin should use `StrictMath`. On iOS, Darwin libm can differ by about 1 ulp, so vectors carry a `tolerance`. Counts and categorical outputs must always match exactly.
7. **Strings in results.** Some functions return Italian labels ("Altro", "Oggi", "Dovute", cadence names). They are catalog keys. Translate them through the shared catalog runtime lookup, never by hand.

## 4. Vector file format

```json
{
  "topic": "expenses",
  "source": "lib/calc/expenses.ts",
  "fixtures": { "...": "optional shared inputs referenced by vectors as \"fixture\"" },
  "vectors": [
    { "id": "expenses.kpis.mese.2026-10-16.2026-10-16",
      "function": "computeKpis",
      "input": { "fixture": "transactions+budgets", "period": "mese", "referenceDate": "2026-10-16", "today": "2026-10-16" },
      "expected": { "speso": 147.55, "budgetTotale": 450, "budgetRimanente": 302.45, "giorniRimasti": 15, "mediaGiornaliera": 9.221875, "mediaGiornalieraPeriodoPrecedente": 11.016666666666667 },
      "tolerance": 1e-9,
      "notes": "optional" }
  ]
}
```
- `tolerance` is an absolute tolerance for numbers. `0` means exact. `null` means an error is expected (assert the error kind; the Italian message is only a key). String outputs (formatting, labels) are always compared byte-exact.
- Dates in `input` and `expected` are `YYYY-MM-DD` strings. Month indices in `{year, month}` objects are **0-based** (JS `getMonth()`).
- Each platform writes a small adapter per `function` name that maps `input` to the native call. Unknown function names must fail the test run, so new vectors can't be silently skipped.
