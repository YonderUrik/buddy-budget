## 2. Conventions and constants

- Money: `Double` (JS number). **Every amount in a schedule is rounded to cents with `round2` at each step**; replicate
  the exact order of operations, not just the formula.
- Rates: `annualRate` is the **nominal annual rate (TAN) in percent** (6.5 = 6.5 %). Monthly rate `i = annualRate / 1200`.
  Interest of a period = `residual × annualRate / 1200`. Installments are monthly, in arrears (French / "rata costante").
- Dates: ISO `YYYY-MM-DD` strings, compared **lexicographically**. No time zones. "Today" = `todayIso()` = UTC date of
  `now` (`now.toISOString().slice(0,10)`) — on device use the UTC calendar date, not local, to match the server.
- Only debt kind `loan` is supported (`credit_line` rows are ignored by the view; the feature was removed).

## 3. Primitives (`lib/calc/amortization.ts`)

### 3.1 `round2(value)`
`Math.round((value + Number.EPSILON) * 100) / 100`. JS `Math.round` rounds .5 **towards +∞** (so −1.005 → −1, not −1.01).
Swift: `((value + .ulpOfOne) * 100).rounded(.down)`-style is wrong — use `floor(x * 100 + 0.5) / 100` on `x = value + 2.220446049250313e-16`.
Kotlin: `Math.floor((value + Math.ulp(1.0)) * 100 + 0.5) / 100`. (`Number.EPSILON` = 2.220446049250313e-16.)

| value | expected |
|---|---|
| 1.005 | 1.01 |
| 2.675 | 2.68 |
| −1.005 | −1 |
| 0.125 | 0.13 |
| 1234.5649 | 1234.56 |

### 3.2 `installmentAmount(principal, annualRate, installments)`
`i = annualRate/1200`; if `i == 0` → `principal / n`; else `principal·i / (1 − (1+i)^−n)`; result `round2`.
Throws if `principal ≤ 0` or `installments ≤ 0` (also NaN).

|---|---|---|---|
| 10000 | 6.5 | 60 | 195.66 |
| 200000 | 3.2 | 360 | 864.93 |
| 1200 | 0 | 12 | 100 |
| 1000 | 0 | 7 | 142.86 |
| 15000 | 9.9 | 48 | 379.72 |
| 0 | 5 | 10 | error |

### 3.3 `addMonthsClamped(date, months, anchorDay?)` — end-of-month rule
`total = y·12 + (m−1) + months` (months may be negative; `floor` division), day = `min(anchorDay ?? d, daysInMonth)`.
The **anchor day** is preserved across short months: a Jan-31 plan goes 31 Jan → 29 Feb → 31 Mar → 30 Apr.
Schedules always use the day of the plan's `firstInstallmentDate` as anchor (also for segments added after events).

| 2024-01-31 | 2 | – | 2024-03-31 |
| 2023-01-31 | 1 | – | 2023-02-28 |
| 2024-02-29 | 1 | 31 | 2024-03-31 |
| 2024-03-15 | −3 | – | 2023-12-15 |
| 2024-11-30 | 3 | – | 2025-02-28 |

### 3.4 `buildSegmentSchedule({firstDueDate, anchorDay?, principal, annualRate, installments, installment?, firstNumber=1})`
Validation: `installments` integer ≥ 1, `principal > 0`. `installment` defaults to `installmentAmount(...)`.
```
residual = round2(principal)
for k in 0..<n:
  interest = round2(residual * annualRate / 1200)
  isLast   = k == n-1
  capital  = isLast ? residual : round2(min(installment - interest, residual))
  paid     = isLast ? round2(residual + interest) : installment
  residual = round2(residual - capital)
  row(number = firstNumber+k, dueDate = addMonthsClamped(firstDueDate, k, anchorDay), installment = paid, interest, capital, residual)
```
The **last installment absorbs all rounding** (it can be slightly higher or lower than the others). If a declared
installment is bigger than needed, capital is capped at the residual, but non-last rows still report the full declared
`installment` even after the residual hits 0, and the last row reports 0 — the web never trims them (quirk, keep it).
Example: 1000 @0 %, 4 rates, declared 600 → installments 600, 600, 600, 0; capitals 600, 400, 0, 0.

### 3.5 Solvers (used by the add form: "fill 3 of 4, we compute the 4th")
Bisection (shared): `bisect(f, lo, hi)` requires `f(lo) ≤ 0 ≤ f(hi)` else returns null; loop up to 200 iterations
while `hi − lo > 1e-12`: `mid=(lo+hi)/2; if f(mid) < 0 lo=mid else hi=mid`; return `(lo+hi)/2`.
Port this exact loop (not a library root finder) so results match to ~1e-12.

- `solveAnnualRate({principal, installment, installments})` → annual %. Errors: any input ≤ 0; `installment·n < principal − 0.005` ("installments don't even cover the principal"); no root in [0,100]. `f(r) = pmtExact(principal, r, n) − installment` (unrounded pmt).
- `solveInstallments({principal, annualRate, installment})` → integer n. Error if `annualRate > 0 && installment ≤ principal·rate/1200` (never amortizes). Simulates with cent rounding: `residual=round2(P)`; for n=1…1200: `interest=round2(residual·r/1200)`; if `residual+interest ≤ installment·1.01` return n; `residual=round2(residual+interest−installment)`. Error after 1200.
- `solvePrincipal({annualRate, installment, installments})` → `round2(installment·(1−(1+i)^−n)/i)` (or `installment·n` if i=0).
- `computeApr({principal, upfrontCosts, installment, recurringCosts, installments})` → **TAEG** %. `payment = installment + recurringCosts`, `net = principal − upfrontCosts`. Errors: `net ≤ 0`, `payment ≤ 0`, `n ≤ 0`, `payment·n < net`, no root. Monthly `i` by bisection on [0,1] of `f(i) = net − PV(i)`, `PV(i) = payment·(1−(1+i)^−n)/i` (`payment·n` if i=0). Result `((1+i)^12 − 1)·100`. Note: a 0 % loan without costs returns ≈5e-10, not exactly 0 (display formats it as 0,00 %).
- `resolveMissingLoanInput(partial)`: keys `principal, installment, installments, annualRate`; missing = undefined or NaN. >1 missing → error; 0 missing → returned as is; otherwise solve the missing one and set `calculated`.

## 4. Loan plan engine (`lib/calc/debt-plan.ts`) — `buildLoanPlan(terms, events, today)`

`DebtTerms = {startMode, principal, annualRate, installments, firstInstallmentDate, installment?}` (installment =
user-declared; null → computed).

**Theoretical rows** (`buildTheoreticalRows`):
1. Initial segment = `buildSegmentSchedule(first date, principal, rate, installments, declared installment)`.
2. "Anchor" events (`rate_change`, `balance_correction`, `early_repayment`) sorted by date (stable `localeCompare`), applied in order:
   - `frozen` = rows with `dueDate ≤ event.date`; `remaining = rows.length − frozen.length`. If 0 → warning "event after last installment: ignored".
   - `residualBefore` = residual of last frozen row, or `terms.principal`.
   - `rate_change`: `currentRate = event.rate`; new tail from the next due date with `principal = residualBefore`, `installments = remaining`, installment **recomputed**.
   - `balance_correction`: same, but `principal = event.amount` (if `≤ 0` → warning, ignored). Rate unchanged.
   - `early_repayment`: `principal = round2(residualBefore − amount)`.
     - If `≤ 0`: the debt is **closed** on `event.date`: record repayment with `amount = round2(residualBefore)` (clamped), `residualAfter 0`; rows = frozen; `closedOn = date`; **stop processing further events**.
     - `reduce_installment`: tail with same `remaining` count, installment recomputed (lower).
     - `reduce_duration`: keep current installment (`rows[frozen.length].installment`), `n = min(remaining, solveInstallments(principal, currentRate, current))`; if the solver throws, fall back to recomputing the installment with `remaining`.
     - Tail numbering continues (`firstNumber = frozen.length + 1`), anchor day = day of `firstInstallmentDate`. Recorded in `earlyRepayments` with `residualAfter = principal`.
3. **Payments** don't change the plan; they map to rows by `installmentNumber`. Unknown number → warning; duplicate → warning, first wins.

**Status** per row: has payment → `pagata`; else `dueDate ≥ today` → `da_pagare`; else `origine` → `da_confermare`, other modes → `scaduta`.

**Totals** (note the `≤ today` vs `≥ today` asymmetry: a row due *today* is `da_pagare` but counts as *past* for totals):
- `past = rows with dueDate ≤ today`, `future = dueDate > today`.
- `residual`: 0 if `closedOn ≤ today`; else the latest of {last past row's residual, last applied early repayment with date ≤ today (wins ties)}; else `principal`. A `balance_correction` does **not** change today's residual until the next row is due.
- `currentInstallment = future[0].installment` or 0; `interestToDate = Σ past.interest`; `interestRemaining = Σ future.interest`; `paidTotal = Σ payment.amount` (all `round2` of the sum).
- `remainingInstallments = future.length`; `endDate = closedOn ?? last row dueDate`; `nextDueDate` = first row with status `da_pagare|scaduta`; `overdueCount`, `unconfirmedCount`; `finished = future.length == 0`; `penaltiesPaid` = Σ penalties of repayments dated ≤ today.
- `residualSeries`: start point at `addMonthsClamped(rows[0].dueDate, −1, anchorDay)` with `round2(principal)`, one per row, one per early repayment (`residualAfter`), sorted by date (stable sort; duplicates kept).

## 5. Early repayment (`lib/calc/early-repayment.ts`, `lib/debts/early-repayment-form.ts`) — CLIENT

`compareEarlyRepayment(terms, events, today, {date, amount, penalty})`:
- `baseline = buildLoanPlan(terms, events, today)`; `baselineInterest = round2(Σ interest of baseline rows with dueDate > date)`; `baselineInstallment` = installment of first baseline row after `date` (or 0).
- For each effect: `plan = buildLoanPlan(terms, events + [early_repayment{date, amount, penalty, effect}], today)`; `interestAfter` (same rule on new plan); `nextInstallment`; `endDate = plan.totals.endDate`; `remainingInstallments` = rows after date; `interestSaved = round2(baselineInterest − interestAfter)`; `netBenefit = round2(baselineInterest − interestAfter − penalty)`; `monthsSaved = max(0, monthDiff(endDate, baselineEndDate))` where `monthDiff` = Δyear·12 + Δmonth (days ignored); `closesDebt = plan.totals.closedOn != null`.

`simulateRecurringExtra(terms, events, today, monthlyExtra)`: adds an `early_repayment` of `monthlyExtra`, penalty 0,
`reduce_duration`, **on every baseline due date > today**, rebuilds; interest compared over rows with `dueDate > today`;
`extraPaid = round2(Σ applied repayment amounts)` (last one clamped to the residual, events after closure dropped).

Form helpers: `resolvePenalty(amount, text, unit)` → empty text = 0; invalid/negative = undefined (error); `percent` →
`round2(amount·value/100)`, `eur` → `round2(value)`. `previewEarlyRepayment` order of checks: empty amount → `empty`;
amount invalid or ≤ 0 → error; mode `monthly`: finished debt → error, else simulate; mode `once`: missing date → error;
no row after the date → error; invalid penalty → error; else compare.

## 6. Simulators (`lib/calc/debt-simulator.ts`, `lib/debts/overview-insights.ts`) — CLIENT

### 6.1 `compareRefinance(current, today, offer)` (surroga)
`current = {residual, currentInstallment, interestRemaining, endDate}` from `plan.totals`.
`newInstallment = installmentAmount(residual, offer.rate, offer.n)`; `newInterest = round2(newInstallment·n − residual)` (simple, not schedule-based);
`switchCosts = round2(upfront + penalty)`; `newEndDate = addMonthsClamped(today, n)`; `netSaving = round2(interestRemaining − newInterest − switchCosts)`;
`breakEvenMonths = ceil(switchCosts / (currentInstallment − newInstallment))` only if costs > 0 and monthly saving > 0, else null.

### 6.2 `simulatePayoff(loans, monthlyExtra, strategy, today)` — **unrounded** month loop
Loans with `residual > 0`; `balance = residual`. While any balance > 0.005 and months < 600:
1. `months += 1`; for each open loan: `interest = balance·rate/1200` (no rounding); `totalInterest += interest`; `balance += interest − min(installment, balance + interest)`.
2. `pool = strategy == none ? 0 : monthlyExtra + freed`. Order open loans: snowball → ascending balance; avalanche (and none) → descending rate (**stable sort**, ties keep input order). Pay `min(pool, balance)` to each in order until pool is empty.
3. Any loan with balance ≤ 0.005 not yet closed → append to `closeOrder`/`closings` (`months`, `endDate = addMonthsClamped(today, months)`), set balance 0, `freed += installment`.
Result: `totalInterest = round2(sum)`, `endDate = addMonthsClamped(today, months)`. Iterate loans in input order (state array order matters for close order within the same month).
`comparePayoffStrategies` = `{none: (extra 0, none), avalanche, snowball}`.

### 6.3 `buildExitPlan(debts, monthlyExtra, today)` (overview "Come uscirne prima")
Loans = open debts with residual > 0 (`residual`, `annualRate`, `installment = currentInstallment`). Null if none, or if
`none.months ≥ 600` or `avalanche.months ≥ 600` (card hidden). Steps = avalanche closings with
`baselineEndDate` from the `none` run and `monthsSaved = max(0, base.months − c.months)`; `interestSaved = max(0, none.totalInterest − avalanche.totalInterest)` (unrounded).
Note: dates are `today + months`, so they differ from the real plan end dates (simplified model; keep identical).
Vector `buildExitPlan.extra200` → steps auto 2025-12-01 (base 2026-01-01, −1), tv 2026-01-01 (base 2026-03-01, −2); interestSaved 33.420000000000016.

### 6.4 `yearlyInterestShares(debts)`
Open debts with residual > 0: `yearly = residual·annualRate/100`; drop `yearly ≤ 0`; sort desc; `share = yearly/total`. Unrounded.

## 7. Add-debt form (`lib/debts/add-form.ts`) — CLIENT

- `parseAmount(text)`: trim; empty → undefined; **if the text contains a comma**, remove all dots and turn the comma into a dot (Italian format); else parse as-is (`Number(...)`, so `"1.250"` = 1.25!). Non-finite → undefined.
- `resolveAddForm(state)`: parse the 4 fields; fewer than 3 → `{ok:false, message:null}` (no error while typing); non-integer `installments` → error; else `resolveMissingLoanInput`; APR = `computeApr(principal, Σ una_tantum, installment, Σ per_rata, installments)` (costs summed with `round2`, unparsable cost = 0), **null for `fotografia`** or on any APR error.
- `previewAddForm`: requires `YYYY-MM-DD` date; builds the segment schedule (declared installment passed unless it was the calculated field) → `{installment: rows[0].installment, totalInterest: round2(Σ interest), endDate: last dueDate}`.

## 8. Small UI calculations (CLIENT)

- `repaidShare(debt)` (`debt-facts.tsx`): `first = plan.rows[0]`; `total = first.residual + first.capital`; `clamp(1 − totals.residual/total, 0, 1)`; ring label `round(share·100)%`.
- `visibleRowRange(rows, today)`: `pivot` = index of first row with `dueDate ≥ today` (or `rows.length`); range `[max(0, pivot−2), min(len, pivot+8))`.
- `rankInstallmentCandidates(tx, filter, dueDate, expected)`: filter (text/category, `filterTransactions` from expenses), then sort by exact amount match first (`| |amount| − expected | < 0.01`), then by absolute day distance to the due date, then original index.
- Pending banner: unsettled = rows `da_confermare|scaduta`; "mark all" sends `upToInstallment = last unsettled number`; server marks rows with status ≠ paid, number ≤ N and dueDate ≤ today, with plan date and amount.
- Duration text `formatDuration(months)`: "{y} anno/anni" + "{m} mese/mesi", joined with `Intl.ListFormat` conjunction ("4 anni e 5 mesi"); 0 → "0 mesi". Month-year via `Intl.DateTimeFormat(locale, {month:"long", year:"numeric"})`. See formatting-localization.md.

## 9. Overview (`buildDebtsView`) — SERVER, for reference only
Per-debt APR: upfront costs (ignored for `fotografia`), recurring costs, installment = declared or `rows[0].installment`; null on error.
Overview over open (not finished) debts: `totalResidual = totalDebt = round2(Σ residual)`, `monthlyPayment = Σ currentInstallment`,
`interestToDate`/`interestRemaining` over **all** debts, `debtFreeDate = max endDate`, `weightedApr = Σ apr·residual / Σ residual`,
`nextDue` = first unsettled row per open debt sorted by date (max 5), `residualSeries` = today + every future date across debts, value = sum of step series.
Vector `buildDebtsView.overview` documents the output shape the API returns (totalResidual 10166.99, monthlyPayment 1132.8, weightedApr 6.0206, debtFreeDate 2026-02-10).

## 10. Porting risks
1. **Rounding order**: schedules round every intermediate value; `simulatePayoff` rounds nothing until the end; `compareRefinance.newInterest` is `installment·n − residual`, not schedule interest. Do not "fix" any of these on mobile or numbers will differ from the web.
2. **JS `Math.round`** rounds halves toward +∞; Swift `.rounded()` and Kotlin `Math.round`/`roundToLong` differ for negatives/half cases — use `floor(x + 0.5)`.
3. **Bisection** must be ported literally (same bounds, tolerance, iteration cap, midpoint return) for solver vectors to match.
4. **Today's date** is the UTC date on the web (client and server). A device in Italy at 00:30 local is still "yesterday" in UTC; replicate or statuses near midnight will differ from the web.
5. **`parseAmount` quirk**: "10.000" (Italian thousands separator without decimals) parses as 10. Mobile decimal keypads avoid most cases, but if parity matters, port as-is and flag the web bug (recommended fix: treat a dot followed by exactly 3 digits as a thousands separator in `it`/`de` locales — fix on both sides together).
6. **Stable sorts**: events with the same date, payoff ties and candidate ranking rely on stable sorting (Swift `sort` is not guaranteed stable — use an index tiebreaker).
7. Status uses `dueDate ≥ today` while totals use `dueDate ≤ today` (row due today is both "to pay" and "past"): intentional on the web, keep it.
8. `computeApr` for 0 % loans returns ~5e-10 rather than 0; display rounding hides it.
