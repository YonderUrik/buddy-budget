# Diversification — sector/area exposure (look-through), fund overlap, target allocation and next-contribution suggestion

Sources (web repo, read-only): `lib/investments/exposure.ts`, `lib/investments/exposure-keys.ts`,
`lib/investments/index-profiles.ts`, `lib/investments/overlap.ts`, `lib/investments/allocation.ts`,
`lib/investments/analysis-view.ts`, `components/domain/investments/diversification/*`, `components/domain/investments/allocation/*`.

Machine-readable golden vectors: [`vectors/exposure.json`](vectors/exposure.json) (14 cases, generated by running the
TypeScript sources; `tolerance` 1e-9 absolute; the matched index profile is serialised as `{profileId, useSectors, broad}`).

**Recommendation.** Exposure, overlaps and allocation drift come from the server with the investments view. Port
`suggestContribution` (water-filling, ~40 lines), `roundedCurrentWeights` and `isCompleteTarget` 1:1 — they react to
user input. Keys (`tecnologia`, `nord_america`, …) are stable identifiers; their labels are in the shared string
catalog (`SECTOR_LABELS`, `AREA_LABELS`, `EXPOSURE_SOURCE_LABELS` are Italian source strings).

## 2. Keys and constants

- Equity sectors (11): `tecnologia, finanza, salute, industria, consumi_ciclici, consumi_difensivi, comunicazioni,
  energia, materiali, servizi_pubblici, immobiliare`; non-equity: `obbligazioni, liquidita, materie_prime, crypto, altro`;
  plus `non_classificato`.
- Areas: `nord_america, europa, italia, giappone, pacifico, emergenti, nessuna` + `non_classificato`. Country → area
  mapping and Yahoo country names in `exposure-keys.ts` (IT → italia, JP → giappone, lists for North America, Europe,
  Pacific, Emerging). ISIN country = first two letters, `XS`/`EU` → none.
- `WEIGHT_EPSILON = 1e-6`, `MOSTLY_NON_EQUITY = 0.5`, `MIN_OVERLAP_SHOWN = 0.2`, `ALLOCATION_TOLERANCE = 0.05`,
  `MIN_SUGGESTION_SHARE = 0.1`, `TARGET_SUM_TOLERANCE = 0.0001`.
- `INDEX_PROFILES` (`index-profiles.ts`): 8 hand-maintained index estimates (all_world, world, sp500, nasdaq100,
  emerging, europe, japan, ftse_mib) recognised by **regex on the instrument name**, with area weights, optional sector
  weights and a `broad` flag; factor ETFs (`small cap|mid cap|momentum|value|quality|min vol|dividend|high yield|equal
  weight`) use areas only; sector/thematic ETFs match nothing. If ported, ship this table as JSON data, not code.

## 3. Resolution per instrument — `resolveInstrumentExposure(instrument, profile, manual)`

Sectors, first match wins: manual → by type (`crypto` → crypto 1, `etc` → materie_prime 1, `obbligazione` →
obbligazioni 1) → Yahoo profile (stock: its sector key; fund: equity sectors scaled by the stock share of the asset mix,
plus bond/cash/other shares; skipped when no sectors and stock ≥ 50% or unknown) → index estimate (only if `useSectors`)
→ none. Areas: manual → `crypto`/`etc` → `nessuna` 1 → stock: Yahoo country → stock/bond: ISIN country (never for
ETF/fund, whose ISIN is the domicile) → index estimate → none. Each dimension then goes through `completeWeights`:
drop unknown keys and values ≤ 1e-6, rescale to 1 if the sum exceeds 1, otherwise put the remainder (> 1e-6) in
`non_classificato`.

## 4. Aggregation — `aggregateExposure(positions, exposures, dimension)`

`total = Σ value` (value > 0); each key gets `Σ value × weight` (instruments without exposure = 100% non_classificato);
drop slices ≤ `total × 1e-6`; `share = value/total`; sort by value desc with `non_classificato` always last;
`classifiedShare = 1 − share(non_classificato)`. Insights: top equity sector if share ≥ 10%; top classified area
(excluding `nessuna`) plus Italy if ≥ 5% (`Math.round(share × 100)` + "%").

## 5. Overlap

`normalizeCompanyName`: lowercase, drop dots, punctuation `,'’()&-` → space, remove corporate suffixes
(`inc, corp, co, ltd, plc, sa, spa, nv, ag, se, class a-c, cl a-c, holding(s), group`…), collapse spaces.
`baseTicker`: uppercase, text before the first dot. Two holdings match on `t:<baseTicker>` or `n:<normalizedName>`.
`holdingsOverlap(a, b)` = Σ `min(wA, wB)` over greedy one-to-one matches (top-10 holdings only → a guaranteed minimum).
Fund pair: same index profile and same `broad` → 1 (`stesso_indice`); both broad → Σ min of area weights
(`aree_indici`); else holdings (`primi_titoli`); shown when ≥ 0.2, sorted desc. Stocks inside funds:
`viaFundValue = fundValue × weightInFund`, `totalValue = direct + Σ via`, sorted desc.

## 6. Allocation — `analyzeAllocation`, `suggestContribution`

Rows = union of target ids and priced held ids, minus unpriced ones. `currentWeight = value/total`, `drift = current −
target`, status `in_linea` if |drift| ≤ 0.05 else `sotto`/`sopra`; sorted by drift ascending; `maxDrift = max |drift|`.
`suggestContribution(analysis, amount)` (amount > 0): candidates = rows with target > 0; **water-fill**: sort by
`value/weight`, grow the set while the level `λ = (amount + Σvalue)/Σweight` exceeds the next candidate's `value/weight`;
buy `weight·λ − value` (> 0). While more than one buy exists and the smallest is < 10% of the amount, drop it (and every
candidate that got no buy) and recompute. Output sorted by amount desc with `weightAfter = (value + buy)/(total + amount)`.
`roundedCurrentWeights`: `Math.round(share × 100)` per priced position, drop zeros, sort by percent desc, give the
rounding remainder to the first, return `percent/100`. `isCompleteTarget`: non-empty and |Σ weight − 1| ≤ 0.0001.
