# German financial planning (DE) — tax, income, pensions, retirement

Sources: `lib/financial-planning/{schema,registry,portfolio,income,projections}.ts`,
`lib/financial-planning/countries/{de,de-avd,de-pension}.ts`, `components/domain/financial-planning/*`,
`app/api/financial-planning/route.ts`, `lib/localization/planning-availability.ts`.
Vectors: [`vectors/financial-planning-de.json`](vectors/financial-planning-de.json) (52 vectors, generated by running the TS code).

## Availability (product switches)
`PLANNING_AVAILABILITY.DE = { tax: true, income: true, pension: false, retirement: false, simulations: false }`.
So for DE users today only **Tax** (`/investimenti/tasse`) and **Income** (`/investimenti/proventi`) screens are visible;
pension (incl. AVD) and retirement editors exist in code but are hidden. Mobile must read the same switches (ideally from
an API/feature-flag payload, not hardcoded) and implement the hidden parts only when they are switched on.

All rules are **2026-only** and fail closed: `germanRules(year)` throws for any year ≠ 2026; the plan schema allows
`tax.year = 2026` only. The plan is a versioned JSON document stored per user+country.

Date caveat: the DE editors compute "today" as `new Date().toISOString().slice(0,10)` — the **UTC** date (elsewhere the
app uses local dates). Between 00:00 and 01:00/02:00 local time in Germany "today" is still yesterday. Mobile should
replicate (use UTC date for these screens) or the server should supply `todayKey`.

## Rounding helpers
- `cents(n) = round((n + Number.EPSILON) × 100) / 100` (JS `Math.round` = round half up toward +∞; for negatives
  `Math.round(-2.5) = -2`). Swift/Kotlin: implement as `floor(x + 0.5)` on the scaled value, **not** banker's rounding and
  not `rounded()` (which rounds half away from zero).
- Solidarity surcharge: `floor((x × 0.055 + 1e-9) × 100) / 100` (truncate to cents).
- `round` in de-avd = `Math.round(n × 100) / 100` (no epsilon).
- `germanIncomeTax` floors the base to whole euros and the tax to whole euros.

## Formulas

### `fundTaxableShare(kind)` = `kind == "unknown" ? null : 1 − exemption[kind]`
(foreign-property yields `0.19999999999999996` in doubles — keep the double, don't round.)

### `germanCapitalTax(profile, shareGains, generalIncome)` (Abgeltungsteuer scenario)
```
sharesAfterLoss = shareGains − profile.shareLosses
remainingShareLosses = max(0, −sharesAfterLoss)
pooled = max(0, sharesAfterLoss) + generalIncome + otherCapitalIncome − generalLosses
remainingGeneralLosses = max(0, −pooled)
allowance = max(0, (joint ? 2000 : 1000) − allowanceUsedElsewhere)
usedAllowance = min(allowance, max(0, pooled)); taxable = max(0, pooled − usedAllowance)
foreignCredit = min(verifiedForeignCredit, taxable × 0.25)
capitalTax = cents((taxable − foreignCredit/0.25) / (1/0.25 + churchRate))     // §32d church-tax formula
solidarity = floor((capitalTax × 0.055 + 1e-9) × 100)/100
church = cents(capitalTax × churchRate); total = cents(capitalTax + solidarity + church)
```
Share losses never offset dividends; losses carry forward without expiry.

### `germanFundAdvance(fund)` (Vorabpauschale 2026, received 2027)
`growthCap = max(0, end − start + distributions)`; `base = min(start × 0.032 × 0.7, growthCap)`;
`gross = max(0, base − distributions) × (13 − acquisitionMonth)/12`; returns `{gross: cents(gross),
taxable: share == null ? null : cents(gross × share), receiptYear: 2027}`.

### `germanIncomeTax(x, joint=false)` — §32a 2026 tariff
`d = joint ? 2 : 1`; `x' = floor(max(0,x)/d)`; `y = (x'−12348)/10000`; `z = (x'−17799)/10000`;
tax = 0 (x' ≤ 12348); `(914.51y + 1400)y` (≤ 17799); `(173.10z + 2397)z + 1034.87` (≤ 69878);
`0.42x' − 11135.63` (≤ 277825); else `0.45x' − 19470.38`. Result `floor(tax) × d`.

### `germanCrypto(plan)` (§23 private sales, tax year only)
For sales whose `sold` starts with the tax year: `anniversary = (acqYear+1) + acquired[4:]` (string);
`gain = proceeds − cost − fees`; `sold > anniversary` (string compare) → exempt, else short-term (seed with
`cryptoOtherGains`). `taxable = shortTerm < 1000 ? 0 : max(0, shortTerm − lossCarryforward)` (threshold, not allowance).
`incomeTax = germanIncomeTax(other + taxable, joint) − germanIncomeTax(other, joint)`.
`remainingLoss = shortTerm < 0 ? carry − shortTerm : shortTerm < 1000 ? carry : max(0, carry − shortTerm)`.

### `germanPortfolioReport` (server-side recommended — summary only)
Transactions with `date ≤ today` and year ≤ tax year, sorted by date, then type order
`split 0, acquisto 1, dividendo/cedola 2, vendita/rimborso 3, rettifica 4`, then createdAt, then id. FIFO lots per
`portfolioId:statementAccountKey|"manual":instrumentId`; acquisition unit cost `price × fx (÷100 for % nominal) + fees/q`;
splits scale lots; sales consume lots FIFO; gain `q × price × fx (÷100) − fees − basis − priorAdvances(funds)`, × partial
exemption share; basket `shares` for stocks, else `general`; dividends/coupons `gross × fx × share` to `general`.
Issues (`currency` if user currency ≠ EUR, `history` unless confirmed, `classification`, `fund-history`, `legacy`
(lots before 2009, funds before 2018), `unsupported`, `missing-lots`, `invalid`) **block the estimate** (`estimate = null`).
Crypto is skipped here (handled by `germanCrypto`).

### `germanIncomeForecast` (server-side recommended)
Uses the shared dividend forecaster with tax rate 0, then for each future event (excluding redemptions) adds
`gross × share` to general income and computes the **incremental** annual tax (`total_after − total_before`);
`net = gross − incremental`. With `futureForecast = "constant-2026"` later years restart from the remaining losses with
2026 rules and are flagged `benchmark: true`; otherwise events outside 2026 get `net = null`.

### AVD (Altersvorsorgedepot, 2027 reform)
`germanAvdAllowance(plan, contributionYear=0)`: `contribution = monthly × 12`;
eligible iff `contribution ≥ 120 && eligibility ≠ none && (eligibility ≠ indirect || spouse ≥ 120)`;
`basis = indirect ? spouseAnnualContribution : contribution`;
`basic = eligible ? min(basis,360)×0.5 + max(0, min(basis,1800) − 360)×0.25 : 0`;
`base = indirect ? min(175, basic) : basic`;
`children = eligible ? count(childAllowanceYears where years > contributionYear) × min(basis, 300) : 0`;
`bonus = eligible && direct && starterBonus && ageAtStart < 25 && contributionYear == 0 ? 200 : 0`;
`total = round2(base + children + bonus)`; `deduction = direct ? min(contribution, 1800) + total : 0`.
`germanAvdTaxBenefit`: `saving = incomeTax(I) − incomeTax(max(0, I − deduction))`; `extraRefund = max(0, saving − total)`.
`projectGermanAvd(plan, referenceYear)`: monthly rate `(1+r)^(1/12)−1`; `delay = max(0, startYear − referenceYear)`;
per year: 12 × `capital = capital(1+m) + (active ? monthly : 0)`, then `+ grant(year − delay)` if active.
`lumpSum = capital × lumpSumRate`; drawdown `months = (endAge − startAge) × 12`, `p = (1+payoutReturn)^(1/12)−1`,
`monthlyGross = provider ? plan.monthlyGross : |p|<1e-12 ? (capital−lump)/months : (capital−lump)·p/(1−(1+p)^−months)`.

### `projectGermanPension(plan, referenceYear = 2026)`
AVD enabled → `projectGermanAvd`. Otherwise `m = (1+nominalReturn)^(1/12) − 1`, `n = years × 12`,
`projected = capital(1+m)^n + (|m|<1e-12 ? contrib·n : contrib((1+m)^n − 1)/m)`.
Statutory: `monthlyGross = (points + years × annualPoints) × 42.52 × accessFactor`, capital 0.
Others: `monthlyGross = paymentMode == income ? plan.monthlyGross : 0`, `lumpSum = capital mode ? projected : 0`.

### `germanPensionNet(payments, plan)` and `germanRetirement(plan)`
See the source for the full branch list; key rules: taxable share of statutory/Rürup pensions by start year
(`≤2005: 0.5; ≤2020: 0.5+0.02(y−2005); ≤2022: 0.8+0.01(y−2020); else min(1, 0.82+0.005(y−2022))`), private annuity
earnings share by age table (EStG §22), KVdR health = half of `(14.6% + additional)` on statutory (capped at ceiling) plus
full rate on occupational above the 197.75 exemption, care `3.6% (+0.6% childless, −0.25% per child under 25 beyond the
first, max 4)`, €102 allowance once, incremental income tax and progressive solidarity
(`min(tax × 0.055, (tax − threshold) × 0.119)`, threshold 20350 / 40700 joint). Unknown tax treatments return
`net = null` with `issues` (UI must show "confirm treatment").
`germanRetirement`: accumulates liquid capital with `wealthAfterYears` (see FIRE spec), adds discounted net lump sums
received before retirement, then simulates 50 years: `withdrawal = max(0, spending − pension)/(1 − withdrawalTaxShare)`
at the **beginning** of the year, `capital = (capital − withdrawal)(1 + realReturn)`, `depletedAfter` = first year it goes
negative, `currentTarget = spending/(1 − withdrawalTaxShare)/withdrawalRate`. Pensions are deflated by
`(1+inflation)^yearsFromToday` and reduced by `pensionDeductionRate` in manual mode.
