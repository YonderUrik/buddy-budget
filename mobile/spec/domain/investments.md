# Investments — positions, average cost (PMC), gains, valuation, composition, FX

Sources (web repo, read-only): `lib/calc/investments.ts`, `lib/calc/fx.ts`, `lib/investments/view.ts`,
`lib/investments/data.ts`, `lib/queries/investments.ts`, `lib/queries/investments-view.ts`,
`lib/investments/broker-filter.ts`, `app/api/investments/overview/route.ts`.

Machine-readable golden vectors: [`vectors/investments.json`](vectors/investments.json) (16 cases) and
[`vectors/fx.json`](vectors/fx.json) (6 cases), generated by running the TypeScript sources with `tsx`
(script kept out of the repo; values verified identical under the default zone (CEST), `TZ=Pacific/Auckland` and
`TZ=America/Los_Angeles`). Both apps load these files in unit tests and assert `expected` within `tolerance`.
Numbers in the JSON are rounded to 12 significant digits; a `tolerance` of `1e-9` absolute is always enough.

Related: [italian-taxes.md](italian-taxes.md), [returns.md](returns.md), [risk.md](risk.md), [costs.md](costs.md),
[exposure.md](exposure.md).

## 1. Where each calculation runs today

**Important finding:** the whole Investments section is computed **in the browser**. `GET /api/investments/overview?period=`
returns *raw data* (`InvestmentData`: transactions, instruments, every price row, manual prices, FX rates, benchmark,
inflation index, €STR rates, profiles, targets, tax settings, carry-forwards, dividend events). The route comment says
so explicitly: *"I calcoli (posizioni, valore, grafico) si fanno lato client con `lib/calc/investments.ts`"*.
The client then runs `buildInvestmentsView()` (`lib/queries/investments-view.ts`, `"use client"`), `buildTaxView()`
(`app/(app)/investimenti/tasse/page.tsx`), `buildIncomeView()` (`app/(app)/investimenti/proventi/page.tsx`).

| Calculation | Function(s) | Web runs it | Evidence (client importer) |
|---|---|---|---|
| Price index (manual > provider > transaction fallback) | `buildPriceIndex`, `resolvePrice` | **Client** | `lib/investments/view.ts` via `lib/queries/investments-view.ts` |
| Positions, weighted average cost, realized gain, income | `computePositions` | **Client** | same |
| Portfolio summary (value, day change, unrealized, total gain %, rows, weights) | `computePortfolioSummary` | **Client** | same; also `app/(app)/panoramica/page.tsx` |
| Daily value series / chart sampling | `computeDailyPortfolioValues`, `buildPortfolioSeries`, `samplePeriodSeries` | **Client** | same |
| Composition by type / currency | `computeComposition` | **Client** | `components/domain/investments/portfolio-composition.tsx` |
| Oversold validation | `findOversoldTransaction` | **Server** (`lib/investments/operations.ts`, imports, personal-import confirm/delete) | — |
| FX conversion | `buildFxTable`, `convertAmount`, `fxRateBetween` | **Client** (and server for notifications/sidebar/net-worth) | `lib/queries/performance.ts` |
| Sidebar portfolio chip, net-worth snapshot of investments, email digest | `lib/sidebar/portfolio.ts`, `lib/net-worth/investments.ts`, `lib/notifications/investments-digest.ts` | **Server** | API routes / cron |
| Title (instrument) page statistics | `computeTitleStats` (see risk.md) | **Server** (`GET /api/instruments/[id]/analysis`) | — |

### Recommendation for mobile

Port as little as possible. The engine is already pure and isomorphic TypeScript, so the cheapest and safest path is to
**add server endpoints that return the computed views** and have the apps display them:

1. `GET /api/investments/view?period=&from=&to=&excludeBrokers=` → the JSON-serialisable part of `InvestmentsView`
   (summary, series, byType/byCurrency, returns, periodGain, analysis, income history, costImpact.additions). The web's
   broker filter (`filterInvestmentBrokers`, applied client-side before computing) must become a query parameter.
2. `GET /api/investments/taxes` → `TaxView` (report, bollo, opportunities, sellable positions) — IT only.
3. `GET /api/investments/income` → income view (missing income, forecast, by month, by instrument) — IT only.
4. `POST /api/investments/taxes/simulate-sale` → `SaleSimulation` (debounced ~300 ms while typing) — see italian-taxes.md.

Then the apps only need to port the **interactive** bits that must react instantly (each has vectors):
`simulateCostExclusions`/`reinvestedAmount` (costs.md), `suggestContribution` (exposure.md), `summarizeCosts`/`costDrag`
(costs.md), and — if the chart "inspect a day" overlay is kept — either a per-day series from the server or a port of
`computePortfolioReturns` (returns.md). If the product decides to keep everything on-device (offline mode), port
**everything in this file and in returns/risk/italian-taxes/exposure 1:1**, using these vectors as the acceptance suite.

## 2. Conventions

- **Numbers:** JS `number` (IEEE-754 double). The web **never rounds** inside the investment engine (no `round2`); values
  are only rounded when formatted. Mobile must use `Double` (Swift) / `Double` (Kotlin) — **not** `Decimal`/`BigDecimal` —
  otherwise results drift from the web in the last digits (e.g. the bond vector `costBasis = 8867` is the exact double of
  `10000*98.5*0.01*0.9 + 2`). Keep the **same order of operations** as the TS code.
- **API numerics are strings** (`quantity`, `price`, `fxRate`, `fees`, `taxes`, `grossAmount`, `close`, `perEur`).
  Parsing: `Number(s)`; `fxRate`/`fees`/`taxes` fall back to `1`/`0`/`0` when the parse gives `0`/`NaN`
  (`Number(t.fxRate) || 1`). `grossAmount` may be `null` → treated as `0`.
- **Dates:** `YYYY-MM-DD` strings compared lexicographically. Date arithmetic (`addDays`, `parseDateOnly`, `toDateKey`)
  works on **local midnight** in the browser. "Today" = `startOfDay(new Date())` in the **device local time zone** (unlike
  debts, which use the UTC date). Use a calendar-date type (`LocalDate` on Android, `DateComponents` / a `CalendarDate`
  struct on iOS) so DST never shifts a day.
- **Quantities below `QUANTITY_EPSILON = 1e-9`** are zero: the position is reset (`quantity = 0`, `costBasis = 0`).
- **Transaction types** (`lib/investments/constants.ts`): `acquisto` (buy), `vendita` (sell), `rimborso` (redemption at
  maturity, behaves like a sell), `dividendo`, `cedola` (coupon), `split` (ratio stored in `quantity`), `rettifica`
  (non-cash adjustment from broker imports).
- **Instrument types:** `etf`, `azione` (stock), `obbligazione` (bond), `fondo` (fund), `crypto`, `etc` (ETC/commodity).
- **Price unit:** `unita` (price per unit, multiplier 1) or `percentuale_nominale` (bonds quoted in % of nominal,
  multiplier 0.01; `quantity` is the nominal amount).

## 3. Sorting — `sortTransactions`

Sort by `date` ascending, then by same-day rank: `split` −1 → `acquisto` 0 → `dividendo`/`cedola`/`rettifica` 1 →
`vendita`/`rimborso` 2. The sort must be **stable** (JS `Array.prototype.sort` is stable): equal keys keep input order
(the API returns transactions ordered by date then creation). Rationale: a split is effective from market open; selling
what you bought the same day is legal.

## 4. Price index — `buildPriceIndex`, `resolvePrice`

Candidates per instrument and date, in this insertion order: (1) buy/sell transaction prices (`origin = "operazione"`),
(2) provider closes (`origin = provider id`), (3) manual prices (`origin = "manuale"`). Discard non-finite or `≤ 0` closes.
For the same date keep the candidate with the higher rank — `manuale 3 > any provider 2 > operazione 1` — and on equal
rank the **later** candidate wins (`>=`). `resolvePrice(index, id, date)` = last entry with `entry.date ≤ date`
(binary search, `findLastOnOrBefore`), else `null`.

Note: the transaction-price fallback is used for the portfolio overview but **not** for correlations
(`observedPrices` skips `origin = "operazione"`, see risk.md).

## 5. Positions — `computePositions` / `applyTransaction` (weighted average cost)

All amounts in **user currency**. `m` = price multiplier, `fx` = transaction's `fxRate` (instrument → user currency at
the trade date).

| Type | Effect |
|---|---|
| `acquisto` | `cost = qty·price·m·fx + fees + taxes`; `quantity += qty`; `costBasis += cost`; `investedNet += cost`; `totalBought += cost` |
| `rettifica` | `quantity += qty`; `costBasis += grossAmount·fx` (not counted in investedNet/totalBought) |
| `split` | if `qty > 0`: `quantity *= qty` (cost unchanged) |
| `vendita`, `rimborso` | `sold = min(qty, quantity)`; `avg = quantity > 1e-9 ? costBasis/quantity : 0`; `proceeds = qty·price·m·fx − fees − taxes`; `realizedGain += proceeds − avg·sold`; `costBasis −= avg·sold`; `quantity −= sold`; `investedNet −= proceeds` |
| `dividendo`, `cedola` | `income += grossAmount·fx − taxes − fees` |

After each transaction, `|quantity| < 1e-9` → `quantity = 0, costBasis = 0`. Transactions after `asOfKey` are ignored.
Finally `averagePrice = quantity > 0 ? costBasis / (quantity·m) : null` (so for bonds it is back in % of nominal).
`firstDate` = date of the instrument's first applied transaction.

Edge cases worth testing: proceeds use the **requested** `qty` but cost uses the **capped** `sold` (an oversold sell
inflates realized gain — prevented upstream by `findOversoldTransaction`); withheld `taxes` on a sell **reduce** the
position's realized gain here, whereas the tax engine does **not** deduct them (italian-taxes.md).

## 6. Oversell guard — `findOversoldTransaction`

Replay sorted transactions keeping only quantities (buys and `rettifica` add, split multiplies, sells subtract); return
the first sell/redemption leaving `quantity < −1e-9`, else `null`. Run it on the **final** list after an insert, edit or
delete. The server validates this too, so mobile can rely on the API error and use the port only for inline form hints.

## 7. Portfolio summary — `computePortfolioSummary`

For each position (computed up to `todayKey`): add `realizedGain`, `income`, `investedNet`, `totalBought` to totals
(closed positions included). For open positions (`quantity > 0`) add `costBasis` and value them:

- `lastPrice = resolvePrice(index, id, todayKey)`; `value = convert(quantity·close·m, instrumentCcy → userCcy, todayKey)`.
  Missing price **or** missing FX → `value = null`, `unpricedCount += 1`, excluded from `totalValue`.
- `unrealizedGain(row) = value − costBasis`; `unrealizedGainPct = (value − costBasis)/costBasis` (null if cost 0).
- **Day change:** previous price = `resolvePrice(index, id, lastPrice.date − 1 day)`; valued with **today's** FX and
  today's quantity. Only positions that have both enter `dayBase` (today's value) and `previousValue`.
  `dayChange = previousValue > 0 ? dayBase − previousValue : null`; `dayChangePct = dayChange / previousValue`.
- `totalGain = unrealizedGain + realizedGain + income`; `totalGainPct = totalBought > 0 ? totalGain / totalBought : null`
  (denominator is *everything ever bought*, fees included — not the current cost basis).
- `weight(row) = value / totalValue` (null if unpriced or total ≤ 0). Rows sorted by `value` desc, unpriced last
  (`-Infinity`), stable.

## 8. Daily values and chart series

`computeDailyPortfolioValues(from, to)`: iterate every **calendar** day; apply that day's transactions first; then
`value = Σ convert(quantity·close·m)` with the last price on/before the day and that day's FX (instruments without price
or FX contribute 0, silently); also emit cumulative `invested` (Σ investedNet), `bought` (Σ totalBought), `income`.

`samplePeriodSeries(daily, period)`: `1mese`/`3mesi` → every day, label `d MMM` (`it-IT` hard-coded in the calc file —
mobile should localise via formatting-localization.md); `1anno`/`max` → one point per calendar month, the **last** day
present in that month, label `MMM yy`. `periodStartKey(transactions, period, today)` = start of the net-worth period
(`getNetWorthPeriodRange`: today minus 1/3/12 months with end-of-month clamping; `max` = first transaction) but never
before the first transaction. `buildPortfolioSeries` clamps a custom range's `to` to today and samples custom ranges
daily.

## 9. Composition — `computeComposition(rows, "type" | "currency")`

Sum `value` of rows with `value > 0` by instrument type or currency; `share = value/total`; sorted by value desc.

## 10. FX — `lib/calc/fx.ts`

Rates come as `perEur` (1 EUR = x units; ECB, EUR pivot). `buildFxTable` drops non-finite/≤0 rates, keeps the last row
for a duplicate date, sorts by date. `getPerEur(ccy, date)`: `EUR → 1`; else last rate on/before date; none → `null`.
`fxRateBetween(from, to) = perEur(to) / perEur(from)` (1 if same currency). `convertAmount = amount × rate` or `null`.
A `null` FX propagates to "unpriced" — never substitute 1.
