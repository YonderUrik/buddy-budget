# Italian investment taxes — capital gains, loss pool (zainetto), funds, crypto, stamp duty (bollo), sale simulator, investment income

Sources (web repo, read-only): `lib/calc/taxes.ts`, `lib/investments/tax-settings.ts`, `lib/investments/tax-report.ts`,
`lib/investments/tax-view.ts`, `lib/investments/tax-insights.ts`, `lib/investments/dividends.ts`,
`lib/investments/income-view.ts`, `lib/localization/financial-country.ts`, `lib/localization/planning-availability.ts`,
`components/domain/investments/taxes/*`. Design spec referenced by the code: `docs/superpowers/specs/2026-09-30-investimenti-fase-4-design.md`.

Machine-readable golden vectors: [`vectors/italian-taxes.json`](vectors/italian-taxes.json) (35 cases, generated by
running the TypeScript sources; Map outputs serialised as objects; numbers rounded to 12 significant digits;
`tolerance` 1e-9 absolute). The engine is an **estimate for understanding the numbers, not a certified tax computation**
— the UI says so and mobile must keep the same disclaimers (strings in the shared catalog).

Country gating: everything in this file is **Italy only** (`FINANCIAL_COUNTRIES.IT.features.taxes = true`).
`investmentTaxReport()` throws for `productCountry === "DE"`; the German Taxes/Income tabs render a different screen
(`PlanningScreen` from `lib/financial-planning`, covered in the financial-planning spec). The bollo rate used by the
Taxes tab is the constant `BOLLO_RATE = 0.002`; the cost analysis (costs.md) instead reads the per-country
`investmentCosts.annualStampDutyRate` (IT 0.002, DE 0).

## 3. Instrument tax settings — `resolveTaxSettings`

Rate: (1) the user's per-instrument override (`instrument_settings.taxRate`, source `manuale`); else (2) **12.5%** if the
instrument is a bond (`type === "obbligazione"`) whose **name** matches
`/\b(BTP|BOT|CCT|CTZ|BTP\s?ITALIA|BTP\s?VALORE|BUND|BUNDESANLEIHE|OAT|BONOS?|TREASURY|T-?BILLS?|T-?NOTES?|GILTS?|REPUBLIC|REPUBBLICA|GOVERNMENT|GOVT)\b/i`
(source `titolo_di_stato`); else (3) the instrument row's rate **only for private instruments** (`createdByUserId != null`),
falling back to 0.26 (source `strumento`). Shared instruments ignore the stored rate (it was chosen by whoever created
them first). Harmonized (UCITS): user override → private instrument's flag → presumed `true`; forced `true` for
non-funds. Mobile: the regex must be ported verbatim (ICU and Java regex both support `\b` and `(?i)`).

## 4. Realized gains — `computeRealizedGains(transactions, instruments, toKey)`

Replays sorted transactions per instrument with a weighted-average cost state `{quantity, cost}`:

- `acquisto`: `quantity += q`; `cost += q·price·m·fx + fees + taxes`.
- `rettifica`: `quantity += q`; `cost += grossAmount·fx`.
- `split`: `quantity *= q` if `q > 0`.
- `vendita`/`rimborso`: `sold = min(q, quantity)`; `average = quantity > 1e-9 ? cost/quantity : 0`;
  `cost_sold = average·sold`; **`proceeds = q·price·m·fx − fees`** (withheld `taxes` are **not** deducted — they don't
  reduce the taxable base, unlike `computePositions`); `gain = proceeds − cost_sold`; category =
  `taxCategoryOf(type, gain)`; `rate = crypto ? cryptoTaxRate(year) : instrument.taxRate`; `withheld = taxes`;
  `nonHarmonized = category === "capitale" && !harmonized`. Then `cost −= cost_sold`, `quantity −= sold`, reset when
  `quantity < 1e-9`.

`taxCategoryOf`: `crypto` → `"crypto"`; ETF/fund with `gain > 0` → `"capitale"` (redditi di capitale: taxed in full,
**cannot be offset** by the loss pool); everything else, **including ETF/fund losses**, → `"diversi"` (redditi diversi:
gains offset by and losses fed into the zainetto).

`toBaseEquivalent(amount, rate) = amount·rate/0.26` — a 12.5% gain/loss "weighs" 48.08% at the 26% base.

## 5. Yearly report — `computeTaxReport({transactions, instruments, regime, manualLosses, todayKey})`

Years run from the first transaction/manual-loss year (≤ current year) to the year of `todayKey`, each initialised to
zeros. A **loss entry** is `{year, expiresYear = year + 4, amount, remaining, origin: "calcolata"|"manuale", crypto}`;
entries are kept sorted by `year` (stable); `consumeLosses(amount, year, crypto)` takes from the **oldest** usable entries
(`entry.crypto === crypto`, `remaining > 0`, `expiresYear ≥ year`) and returns the amount used.

For each year `y`:

1. **Amministrato** (broker withholds per trade): manual losses of year `y` are added **at the start** of the year.
2. For each realized event of the year (in transaction order): `withheld += event.withheld`;
   - `crypto`: accumulate `netCrypto`; gains → `cryptoGains`, losses → `cryptoLosses`.
   - `capitale` (fund gain): `tax = gain·rate`; `fundGains += gain`; `taxOnFunds += tax`; count non-harmonized; in
     amministrato `event.lossesUsed = 0`, `event.estimatedTax = tax`.
   - `diversi`: `eq = toBaseEquivalent(gain, rate)`; `gains`/`losses` get the **nominal** amount. Amministrato: if
     `eq ≥ 0` → `used = consumeLosses(eq)`, `tax = (eq − used)·0.26`; else add a loss entry of `−eq` (base 26%) and
     `lossesCreated += −eq`. A loss only offsets **later** gains (order matters). Dichiarativo: `netDiversi += eq`.
3. **Dichiarativo** (self-declared): after the loop, net annual: `netDiversi > 0` → consume zainetto, tax at 26%;
   `< 0` → new loss entry. Manual losses of year `y` are added **after** netting (usable from `y+1`).
4. **Crypto** (always annual, both regimes): `netCrypto > 0` → exempt if `y ≤ 2024 && netCrypto ≤ 2000`; otherwise
   consume the **crypto-only** pool (nominal amounts, not base-26) and tax at `cryptoTaxRate(y)`. `netCrypto < 0` → crypto
   loss entry. Note: the exemption is all-or-nothing (≤ 2000 → zero, > 2000 → the whole amount is taxed).
5. `estimatedTax = taxOnGains + taxOnFunds + taxOnCrypto`.
6. If `y < currentYear`: entries with `expiresYear === y` and `remaining > 0` expire (`lossesExpired += remaining` for
   non-crypto; crypto expiries are not counted) and are set to 0.

Finally dividends/coupons up to `todayKey` add `incomeGross += grossAmount·fx` and `incomeWithheld += taxes` per year
(transactions in years outside the range are ignored). `bollo` is filled later by `buildTaxView`. `losses` returned =
entries with `remaining > 0.005` (half a cent).

Per-event `lossesUsed`/`estimatedTax` stay `null` in dichiarativo and for crypto.

`lossesByExpiry(losses, crypto=false)` groups remaining amounts by `expiresYear`, ascending.

## 6. Stamp duty — `computeBollo(daily, todayKey)`

Input = daily portfolio values from the first transaction to today (`computeDailyPortfolioValues`). Per calendar year:
`value` = value on the **last day present** in that year (for the current year: today); `days` = number of days with
`value > 0`. For the current year (`estimate = true`) days are **projected**: from the first invested day of the year to
31/12 inclusive (`round((UTC(31/12) − UTC(first))/86400000) + 1`). `share = min(1, days / daysInYear)` (366 in leap
years: `y%4==0 && (y%100!=0 || y%400==0)`). `bollo = value × 0.002 × share`. No minimum/maximum caps are applied
(the real bollo has a €14,000 cap for non-individuals and a €34.20 fixed duty on bank statements — not modelled).

## 7. Sale simulator — `simulateSale`

Returns `null` unless `quantity > 0 && price > 0`. Builds a synthetic `vendita` dated `todayKey` (`fees` default 0,
`taxes` "0"), runs `computeTaxReport` **before** and **after**, and for the current year returns:
`proceeds`, `cost`, `gain`, `category`, `nonHarmonized` of the synthetic event; `taxDelta = after.estimatedTax −
before.estimatedTax` (can be negative in dichiarativo, where a loss lowers the year's tax); `lossesUsed` and
`lossesCreated` deltas (crypto + non-crypto); `net = proceeds − taxDelta`. The card uses the last price in instrument
currency and `fxRate = convertAmount(fx, 1, instrumentCcy, userCcy, today)`; positions without price or FX are not
offered.

## 8. Opportunities — `computeTaxOpportunities(rows, instruments, losses, currentYear)`

`expiringThisYear` = Σ remaining of non-crypto entries with `expiresYear === currentYear`. For each open row with an
unrealized gain, excluding crypto: `eq = toBaseEquivalent(unrealized, rate)`; gains of **non-fund** instruments →
`compensableGains`; any loss (funds included) → `losses` with `equivalent = −eq` (positive). Both sorted by equivalent
desc; totals summed.

## 9. Estimated charges for the cost-impact chart — `estimatedTaxCharges(report, todayKey)`

Per year: `remaining = max(0, estimatedTax − withheld)`; skip if `< 1e-6`. Dichiarativo or a year containing any crypto
event → one charge dated `min(YYYY-12-31, todayKey)`. Otherwise spread `remaining` over the year's events pro-rata to
`max(0, event.estimatedTax − event.withheld)`, dated on each event.

## 10. Investment income (Proventi) — `lib/investments/dividends.ts`

Constants: `MATCH_DAYS_BEFORE = 5`, `MATCH_DAYS_AFTER = 60`, `FORECAST_MONTHS = 12`, `GROWTH_YEARS = 5`. The tax rate
per instrument comes from the resolved tax settings (fallback 0.26). Foreign withholding is ignored (net = gross × (1 − Italian rate)).

- `shiftMonths(date, n)`: same day n months later, clamped to the month's last day (UTC arithmetic).
- `couponDates(terms, from, to)`: walking **backwards from maturity** in steps of `12/frequency` months (frequency 1, 2, 4),
  dates in `(from, to]`, returned ascending. Coupons only for bonds priced in % of nominal with complete user terms
  (`couponRate > 0`, frequency, maturity).
- **Missing income** (`findMissingIncome`): candidates are coupon dates between first buy and `min(maturity, today)` with
  nominal held the day before (`gross = nominal × rate / frequency`), or provider ex-dividend dates after the first buy and
  ≤ today with units held the day before (`gross = units × splitFactorFromExDate × amountPerShareToday`). A candidate is
  covered if an unused registered dividend/coupon exists in `[date − 5d, date + 60d]` (greedy, earliest first);
  dismissed `(instrumentId, date)` pairs are skipped. `estimatedTax = gross × fx(date) × taxRate` (null if no FX).
  Sorted newest first.
- **Forecast** (`forecastIncome`): window = next 12 full calendar months (`(endOfMonth(today), endOfMonth(today + 12 months)]`),
  using **today's** quantity and **today's** FX. Bonds with terms → coupons + redemption at par (`kind "rimborso"`, net =
  gross, excluded from monthly totals). Instruments with provider dividends → ex-dates of the same window one year earlier,
  shifted +12 months (`basis "fonte"`). Otherwise → registered income of that window one year earlier rescaled to today's
  quantity (`basis "storico"`). Bonds with neither → listed in `bondsWithoutTerms`. Monthly buckets `YYYY-MM`.
- `incomeByMonth`: registered dividends/coupons up to today, `gross = grossAmount × fx`, `withheld = taxes + fees`,
  `net = gross − withheld`; 12 months per year, years newest first.
- `dividendGrowth(events, currentYear)`: sum per-share amounts per calendar year for the last 5 complete years; requires a
  positive last year and ≥ 2 paying years; CAGR `(last/first)^(1/(lastYear − firstYear)) − 1`.
- `incomeByInstrument`: trailing-12-month net (`date > today − 12 months`), `yieldOnCost = trailingNet / costBasis`,
  `forecastGross` (excl. redemptions), `currentYield = forecastGross / value`, growth; sorted by forecast desc then
  trailing desc.

## 11. Numeric notes

Doubles, no intermediate rounding (except the `0.005` filter on remaining losses and `1e-6` thresholds). Display
rounds to cents. `Double` on both platforms; do **not** use `Decimal`, or vectors such as
`taxes.toBaseEquivalent.govBond = 480.769230769…` will differ in the last digits.
